# REST API Design with Express

## Overview
Express.js is a minimalist web framework for Node.js that simplifies building robust APIs. Following RESTful principles ensures that APIs are scalable, maintainable, and easy to consume. This note covers key concepts for designing REST APIs with Express, including resource modeling, HTTP methods, status codes, and best practices.

## Why It Matters
- **Industry Standard**: REST is the most common architectural style for web APIs.
- **Scalability**: Stateless interactions enable horizontal scaling.
- **Interoperability**: Well-defined contracts allow seamless integration with clients.
- **Maintainability**: Clear resource organization simplifies evolution.
- **Performance**: Proper use of HTTP caching and conditional requests reduces load.

## Real-World Usage
- **Social Media APIs**: Twitter, GitHub, and LinkedIn offer RESTful endpoints.
- **E-commerce Platforms**: Shopify, Stripe, and PayPal APIs follow REST principles.
- **Cloud Services**: AWS SDKs and Azure REST APIs use RESTful interfaces.
- **Mobile Backends**: Many mobile apps consume REST APIs from Node.js backends.
- **Microservices**: Internal service-to-service communication often uses REST.

## Code Example
```javascript
const express = require('express');
const app = express();
const PORT = process.env.PORT || 3000;

// Middleware
app.use(express.json());

// In-memory storage for demonstration
let users = [
  { id: 1, name: 'Alice', email: 'alice@example.com' },
  { id: 2, name: 'Bob', email: 'bob@example.com' }
];
let nextId = 3;

// GET /users - Retrieve all users
app.get('/users', (req, res) => {
  // Support filtering by query parameters
  const { name, email } = req.query;
  let filtered = users;
  if (name) filtered = filtered.filter(u => u.name.toLowerCase().includes(name.toLowerCase()));
  if (email) filtered = filtered.filter(u => u.email.toLowerCase().includes(email.toLowerCase()));
  res.json(filtered);
});

// GET /users/:id - Retrieve a single user
app.get('/users/:id', (req, res) => {
  const user = users.find(u => u.id === parseInt(req.params.id));
  if (!user) return res.status(404).json({ error: 'User not found' });
  res.json(user);
});

// POST /users - Create a new user
app.post('/users', (req, res) => {
  const { name, email } = req.body;
  if (!name || !email) {
    return res.status(400).json({ error: 'Name and email are required' });
  }
  const newUser = { id: nextId++, name, email };
  users.push(newUser);
  res.status(201).json(newUser);
});

// PUT /users/:id - Update a user (replace)
app.put('/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const index = users.findIndex(u => u.id === id);
  if (index === -1) return res.status(404).json({ error: 'User not found' });
  const { name, email } = req.body;
  if (!name || !email) {
    return res.status(400).json({ error: 'Name and email are required' });
  }
  users[index] = { id, name, email };
  res.json(users[index]);
});

// PATCH /users/:id - Partial update
app.patch('/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const index = users.findIndex(u => u.id === id);
  if (index === -1) return res.status(404).json({ error: 'User not found' });
  const updates = req.body;
  Object.assign(users[index], { ...users[index], ...updates });
  res.json(users[index]);
});

// DELETE /users/:id - Delete a user
app.delete('/users/:id', (req, res) => {
  const id = parseInt(req.params.id);
  const index = users.findIndex(u => u.id === id);
  if (index === -1) return res.status(404).json({ error: 'User not found' });
  users.splice(index, 1);
  res.status(204).send();
});

// Error handling middleware
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Something broke!' });
});

// 404 handler
app.use((req, res) => {
  res.status(404).json({ error: 'Route not found' });
});

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

## Common Mistakes
- **Using Wrong HTTP Methods**: Using POST for updates or GET for deletions violates REST semantics.
- **Incorrect Status Codes**: Returning 200 for errors or 404 for server errors confuses clients.
- **Overloading Endpoints**: Cramming multiple resources into one endpoint (e.g., /users?action=delete).
- **Ignoring Idempotency**: PUT and DELETE should be idempotent; repeated calls should have the same effect.
- **Missing Content-Type**: Not setting `application/json` in responses when returning JSON.
- **Exposing Internal IDs**: Using database IDs directly can leak information; consider UUIDs or opaque tokens.
- **Lack of Versioning**: Not versioning the API (e.g., /api/v1/users) makes breaking changes difficult.
- **Ignoring Security**: Forgetting to validate inputs, authenticate, and authorize requests.

## Interview Question
**Question**: How would you design a RESTful API for a blogging platform with posts and comments? List the endpoints and HTTP methods you would use.

**Answer**: 
- **Posts Collection**: 
  - GET /posts - Retrieve all posts (with pagination/filtering)
  - POST /posts - Create a new post
- **Individual Post**: 
  - GET /posts/:id - Retrieve a specific post
  - PUT /posts/:id - Update a post (replace)
  - PATCH /posts/:id - Partially update a post
  - DELETE /posts/:id - Delete a post
- **Comments on a Post**:
  - GET /posts/:postId/comments - Retrieve comments for a post
  - POST /posts/:postId/comments - Add a comment to a post
- **Individual Comment**:
  - GET /posts/:postId/comments/:commentId - Retrieve a specific comment
  - PUT /posts/:postId/comments/:commentId - Update a comment
  - DELETE /posts/:postId/comments/:commentId - Delete a comment
Additional considerations: authentication, authorization, pagination, sorting, filtering, HATEOAS, error handling, and validation.

## Key Takeaways
- Use nouns for endpoints (resources) and HTTP verbs for actions.
- Follow standard HTTP status codes (200, 201, 204, 400, 401, 403, 404, 409, 500).
- Ensure idempotency for PUT and DELETE.
- Version your API to manage breaking changes.
- Validate and sanitize all inputs.
- Use HTTPS in production to encrypt data.
- Implement proper authentication (e.g., JWT, OAuth) and authorization (RBAC/ABAC).
- Consider rate limiting to prevent abuse.
- Document your API with tools like Swagger/OpenAPI.
