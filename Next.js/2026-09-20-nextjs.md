# Next.js

## Overview
Next.js is a React framework that enables server-side rendering, static site generation, and API routes for building production-grade web applications. It simplifies the development of React applications by providing built-in routing, optimized performance, and seamless deployment capabilities.

## Why It Matters
Next.js addresses key challenges in modern web development: performance, SEO, and developer experience. With features like automatic code splitting, image optimization, and incremental static regeneration (ISR), it allows developers to build fast, scalable applications with less configuration. Its popularity in the industry makes it a valuable skill for full-stack engineers.

## Real-world Usage
- Netflix, Twitch, and GitHub use Next.js for parts of their platforms.
- Many startups and enterprises adopt Next.js for marketing blogs, e-commerce sites, and dashboards due to its hybrid rendering capabilities.
- Vercel, the company behind Next.js, provides seamless deployment infrastructure for Next.js applications.

## Code Example
Here's a simple page demonstrating data fetching with `getStaticProps` for static generation:

```jsx
import Link from 'next/link';

export default function Home({ posts }) {
  return (
    <div>
      <h1>Blog Posts</h1>
      <ul>
        {posts.map(post => (
          <li key={post.id}>
            <Link href={`/post/${post.id}`}>
              <a>{post.title}</a>
            </Link>
          </li>
        ))}
      </ul>
    </div>
  );
}

export async function getStaticProps() {
  // Fetch data from an external API
  const res = await fetch('https://example.com/api/posts');
  const posts = await res.json();

  return {
    props: {
      posts,
    },
    // Re-generate the static page at most once per hour
    revalidate: 3600,
  };
}
```

## Common Mistakes
- **Misunderstanding rendering methods**: Confusing when to use `getStaticProps`, `getServerSideProps`, or `getInitialState` can lead to performance issues or incorrect data fetching.
- **Forgetting to add `key` prop in lists**: As with React, missing keys can cause rendering inefficiencies and warnings.
- **Not optimizing images**: Using regular `<img>` tags instead of Next.js' `Image` component can result in poor performance and layout shifts.
- **Overusing API routes**: While convenient, putting too much business logic in API routes can make the codebase hard to maintain; consider separating concerns.
- **Ignoring environment variables**: Hardcoding secrets or configuration values instead of using environment variables exposed via `process.env`.

## Interview Question
**Question**: Explain the difference between `getStaticProps` and `getServerSideProps` in Next.js. When would you use each?

**Answer**: 
- **getStaticProps**: Used for static site generation (SSG). Data is fetched at build time (or when revalidated with ISR) and the HTML is generated once per request during build. Ideal for content that doesn't change frequently, like blog posts or product listings.
- **getServerSideProps**: Used for server-side rendering (SSR). Data is fetched on each request, allowing for dynamic content that depends on user-specific data (e.g., authentication, cookies). Suitable for personalized dashboards or data that changes frequently.
- Choose SSG when possible for better performance and lower server load; use SSR when you need fresh data on every request.

## Key Takeaways
- Next.js extends React with powerful features for routing, data fetching, and optimization.
- Hybrid rendering (SSG, SSR, ISR) provides flexibility to choose the right strategy for each page.
- Automatic code splitting and prefetching improve navigation performance.
- The framework's conventions reduce boilerplate, allowing developers to focus on building features.
- Mastery of Next.js is highly sought after in full-stack developer roles, especially those involving modern React applications.
